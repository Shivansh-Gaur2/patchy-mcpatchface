# Optional Codex Factory profiles

These templates define named subagents and starting reasoning budgets for Codex. They are not auto-registered by Patchy's plugin manifest. To use them, copy the selected `.toml` files into the target project's `.codex/agents/` directory or your personal `~/.codex/agents/` directory, then reload Codex as required by the installed version. See the [Codex subagent guide](https://learn.chatgpt.com/docs/agent-configuration/subagents) for current profile fields and precedence. Review the files first; they inherit the parent session's host permissions unless a profile or live runtime changes them.

The mapper, designer, and reviewer request `read-only`. The builder requests `workspace-write`. Fast uses one reviewer profile for both contract and implementation axes. Deep may start two independent instances of that profile with one axis assigned to each; submit both reports before sharing them. A security focus belongs only to a changed security boundary and may require a sequential specialist review. Start the builder with the job worktree as its working directory and verify it before edits. A permission mode alone does not prove writes are confined to that directory; live permission controls may override profile settings. Model IDs are deliberately omitted so the profiles inherit the user's configured model. Reasoning levels are starting points and must be supported by that model. Change them to match local policy and validate them on the installed Codex version.

The prompts name the matching Patchy role skill. Skill discovery inside a child session is host-dependent, so the Factory coordinator must also send a bounded role packet and must not assume that the plugin alone registered these profiles.
